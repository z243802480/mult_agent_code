# S95 — Studio 事件账本完整性与坏行隔离

## 触发与参考

S94 的真实 Studio 会话中，主线程显示了一段 `provider_call_seconds` 起头的事件元数据。原始运行时 `user_progress.jsonl` 可解析；Studio 会话 `events.jsonl` 的 2150 行里有一条截断 JSON，读取端把它包装为 `raw.content_delta`，所以内部字段进了主线程。附近序号乱序。Node 事件总线与 Python 模型事件 sink 会跨进程追加同一文件；Node 内部的多路 `appendEvent` 也没有写入队列。参考现有 `session-store.mjs` 的每文件写入串行化、模型事件 sink 与 Studio SSE 游标；借鉴成熟 agent 对事件流单写者及坏记录隔离的边界，不复制实现。

## 本刀范围

- 串行化 Node 对单会话的追加，让 `seq` 与落盘顺序一致；Python sink 以单次二进制追加写完整 JSONL 行，降低跨进程写入交错风险。
- 读取端遇到已损坏的行时只跳过该行，不把任意存储字节包装成用户正文；保留其余可解析事件与运行时证据。
- 给并发追加、既有坏行回放和用户可见正文补确定性回归。用真实 S94 会话文件验证坏行不再进入 API 回放。

## 验收与边界

- Node 并发追加后每行可解析、Node 序号按物理行单调；坏行前后事件仍可读，元数据片段不作为正文返回。
- 运行相关 Studio/Python 测试、文档契约与主路径 smoke；不修改 S94 的真实会话原始证据，不读或提交密钥及既有未跟踪验证目录。
- 跨进程写入仍需真实压力复验；若单次追加不足以稳定保证完整性，下一刀改为单写者汇流，不声称已彻底消除风险。
