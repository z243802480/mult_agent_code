# S100 — 模型能力补丁与驾驭边界审查

## 触发与对标

用户要求核实是否把模型能力缺口写成固定补丁，改以提示词、工具契约、证据回灌和工程边界驾驭模型。S99 文档任务在 Windows 误选 `grep -A5`，此前仅为 GoalSpec/Plan 加 OS 与命令来源提示。审查覆盖 S94 协议修正、S97 结尾证据闸、S99 环境提示、执行模型提示与命令网关。对标 OpenAI Codex 的环境上下文、tool→observation→model 循环，以及 Claude 的结构化工具契约和错误回灌；只借机制，不复制实现。

## 本刀

- 把现存行为逐项归类为通用协议/证据边界、提示词引导、模型特例补丁；结论附代码位置与实证。
- 删除 Windows `ls -la <路径>` 被偷换成“文件存在即成功”的伪 shell 兼容，以及将 `python/python3` 静默改为 harness 解释器的命令重写。模型发出的命令应按原样执行；项目 PATH 优先于作为后备的 harness Python。
- 删除“非零退出码但输出含 Usage 即成功”的内容启发式；只有实际退出码落在默认或显式 `expected_returncodes` 才算成功。
- `run_tests` 属验证工具，退出码必须为 0；不向模型开放重定义“测试通过”返回码的参数。需要检查预期非零的普通命令仍可用 `run_command` 的显式预期码。
- 给 GoalSpec、Plan、执行模型提供一致的真实 OS 与 `run_command` shell 上下文，不建命令黑名单；未知命令失败照实作为 observation 回灌。
- 纠正“尚未观察到工具动作”被写成“产物不存在”的无证据催促，以及执行提示硬编码用户语言为中文。
- 保持权限、写作用域、预算、schema 与真实验证闸；不改模型所决定的下一步。

## 验收

`ls -la` 与 `python3` 不被偷换；单测验证请求原样交给 shell，执行结果按真实退出码报告，`Usage:` 文本不能翻转失败，显式预期返回码仍可成功。三阶段提示含同一环境事实。第一轮空工具轻推只说无执行证据，不虚构产物状态。相关单测/集成测试、Ruff、文档契约通过；既有未跟踪验证目录不入库。
