# S104 — 成功任务的成对成本采样

## 来源与机制

承接总计划 §16.2/S103 交接和用户“继续”。遵循模型选择行动、harness 管权限/预算、独立验证判结果的现有机制。既有小样本不能区分“便宜地失败”和“高效地成功”；本刀先补证据，不预设需要新代码。

## 预注册方案

- 两版代码固定为 48c08a4 与 37516da，复用 WSL Linux/Python/既有本机路由；复制相同单文件 calc.py 缺陷、README 和只读原测试，不添加 Git 仓库。
- 普通 goal 入口，auto 权限/策略、no-research、max-iterations=3。相同 goal 明示工作区无 Git、仅改 calc.py、禁止依赖/工作区外写入。每次独立工作区，原测试哈希固定。
- 三组配对，顺序 A/B、B/A、A/B；一共六次，不按结果挑样本或无限重试。每次 goal 最长 240 秒，超时/暂停照实计失败，停止后保留证据。
- 分离 goal 与显式 Review 调用；记录模型名/provider、工具数/失败数、耗时、输入/输出 token、replan 数，以及独立测试/边界检查/哈希和最终接受状态。两版均成功的配对才比较成功交付成本；其他保留为可靠性观察。
- 不越权解决审批或调整 provider 配额。GLM review 额度错误单列，不把它算成 MiniMax 执行能力问题。样本少，不报行业级成功率或稳定收益。

## 停止与交接

六次完成或连续 provider 不可用后停止，保存汇总与可复跑入口；更新四份 ACTIVE 指针及总计划。只有出现可复现的通用工程缺陷才开代码修复；否则只更新报告与下一步。
