# S105 — 执行上下文构成与安全去重

## 依据与参考机制

总计划 §16.2 / S104 六次样本显示首执行输入约 1.83–1.91 万 token，但尚未支持稳定降本。参考现有 context_prompt_view 的“审计保留全量、模型消费必要视图”机制，检查重复投影；认知与行动仍交模型，不按题目、模型名或回复文本写补丁。

## 实施边界

- 用隔离工作区、真实 ExecuteCommand 装配链和捕获客户端测首个请求组成；该探针不调用 provider、不算真模型通过。
- 只有确认完全重复的内容才删减模型视图，保留原持久化账本、作用域/权限、预算、模型工具 schema、项目指导、当前任务/验收和工具失败观察。复核发现 audit envelope 内仍有独有的策略/预算提示，因此最终不裁剪 envelope，只去掉已被系统提示完整覆盖的 AGENTS.md 副本。
- 不在全局 context_prompt_view 盲目删除未知键；兼容旧/缺失 envelope，未知扩展保留。测试验证原对象不变及必要字段可达。
- 最小实现后使用 S104 同题、既有 MiniMax 路由真跑检查独立测试/哈希/Review→Accept；内容和输入 usage 的减少不等于稳定耗时或货币费用下降。
- 文档契约、相关执行/委派/规划/评审回归、Ruff 和类型棘轮通过；提交推送后按精确 SHA 核对 CI。既有验证目录/本机路由不入库。
