## 最小机制

规划器仅给自己新增的具体方法记录来源，GoalSpec、project.json 配置命令与完整根指导内容中的原样命令保守视为上层要求，配置检查的原样包装也不可修订。根指导独立有界读全（256Ki字符，仅作授权判断，不扩大4k模型提示），不拿提示摘录当完整权威；指导过大/不可读、来源缺失或权威快照变化则不可自动修订。来源由 harness 生成，模型原始 JSON 不能自报授权。旧无来源任务不自动放宽；采用用户/项目检查作替代也不能给它后续可修订权。

新增模型工具 revise_verification，仅能修订当前任务的一条自拟方法。需要实际同任务的失败观察、之后执行的替代方法成功观察、修订理由和覆盖说明；拒绝无执行/拒绝执行/错误任务/过期失败或有副作用的替代证据。工具不执行 shell、不改 acceptance、GoalSpec、完成要求、文件授权、用户/项目检查。原失败和替代观察保留；在既有 schema 验证的 task_board 中原子持久化方法及修订记录。替代成功仅证明其执行结果，语义覆盖由模型说明并接受原验收要求约束，harness 不声称能证明任意两程序等价。

同步当前执行任务的验证字段，避免只改磁盘导致本轮仍使用旧命令；重规划继承来源和历史，不扩写授权。替代方法后再发生潜在写入，仍须重跑，不能借修订取消新鲜度门。既有 task_plan.json 就是可变的 TaskBoard，修订保留原命令和观察引用，不能另造第二份当前计划。
