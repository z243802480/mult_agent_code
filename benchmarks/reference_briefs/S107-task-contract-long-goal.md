# S107 — 任务契约传递与目标驱动自主解题

用户 2026-11-10 进一步明确：关注像主流编码 agent 那样，为完成目标自主工作一到三小时、遇到问题自己解决；不要求凑满时长。承接总计划 §16.2 第 19 行和 S106 已复现的读范围/分阶段验证耦合。

## 实现范围

- PlannerAgent 提示明确每个任务所需只读上下文和局部验证，完整目标验收放在依赖实现完成的整合阶段；不把依赖未完的全套测试强塞给中间任务。
- 归一化保留模型声明的 read_scope、validation_commands，复用既有任务 schema、PathGuard、权限与写范围机制；旧格式缺省保持兼容。模型声明的只读路径不变成写权限；GoalSpec 和最终目标验收不删除。
- 只修通用字段传递与提示，不按题目/模型名改写计划、命令或答案，不新增编排 Wave、维护命令或默认并发写。
- 参考 S106 已查阅的 [Anthropic 长任务机制](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) 与 [OpenCode 工具循环](https://raw.githubusercontent.com/anomalyco/opencode/dev/packages/ai/README.md)：可继续的进度、模型自己选择行动、错误回灌、明确独立验收。

## 验收与停止边界

1. 确定性回归：两个相依任务拿到各自局部验证及 README/只读测试；正常存储/运行时 profile 接线；写范围未扩大、保护路径仍拒绝；旧计划兼容。
2. 修复后冻结代码，用既有可用真 provider，在隔离 WSL 工作区开展一个完整多模块目标。禁用本次进程中未配置的 cheap/strong 路由，回退可用 medium；密钥只由正常运行时读取，不输出或迁移。
3. 单次目标最多 60 分钟和默认预算（200 model calls / 1000 tools 等），正常 auto 权限。任务可提前成功；不靠等待、重复测试或人工拆题凑时长。若提前失败或预算到限，保留记录，不刷样本。
4. 独立验收同时检查需求、完整原测试、额外边界、不变哈希/范围；记录主动诊断修复、重规划、压缩、卡点和人工介入。任务运行期间不手改示例解或通过额外提示替模型解题；产品错误需另记介入。
5. 相关回归、Ruff、类型棘轮、文档契约与精确代码 CI；如未完成，写清运行状态和下一步，不把测试工具绿冒充目标成功。

当前定义的成功：给定完整目标后，模型在既有安全与预算边界内自主完成，并通过独立验收。仅证明一次成功，不外推所有一到三小时任务。
