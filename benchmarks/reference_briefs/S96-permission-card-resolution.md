# S96 — 权限确认后卡片状态归一

## 触发与参考

S93 真实 Studio 会话在批准后继续规划和执行，页面仍显示“待批准”。原始会话三个 job 权限请求均有匹配的 `resolved_job_id`；服务端 `readSessionEvents` 在刷新回放时会过滤已解决请求。当前页面的 `mergeEventLists` 只增不减，SSE 带来解决标记后仍保留旧请求，卡片从旧事件渲染。另 `permitJob` 忽略 HTTP 200 的 `{ok:false}`，`PermissionCard` 在调用返回后误报“已确认”。参考现有 M4 服务端过滤规则、Studio 事件投影与主流 agent 一次性权限确认交互；只借鉴状态一致性边界，不复制实现。

## 本刀范围

- 先用 S93 事件形状给 live merge 建失败复现，再让解决标记从页面事件列表移除对应 job 的 `permission_request`，保留无标记的待确认卡和其余历史事件。
- 批准或拒绝仅在服务端明确 `ok:true` 后显示成功；失败保持可重试并给出错误提示。
- 验证 live 状态、刷新回放和拒绝路径；不修改 Runtime 权限策略或取消原始 JSONL 审计记录。

## 验收

- 确认成功后当前页面不再显示待批准卡，刷新后也不出现；另一个未处理的卡仍可操作。
- `{ok:false}` 或网络失败不显示“已确认/已取消”，卡片仍可重试。
- Studio 定向测试、主路径 smoke、文档契约通过；真实 S93 原会话只读对照，不读取密钥或提交临时工作区。
