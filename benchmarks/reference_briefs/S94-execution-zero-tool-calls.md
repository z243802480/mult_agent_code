# S94 — 执行模型只叙述、不调用工具

## 触发与参考

S93 本地 Studio 真模型小任务在 Goal→Plan 后阻塞：强档执行模型两次调用成功，但只输出“先读文件”“现在修改文件”的叙述，工具证据为零，产物与验证均缺失。证据见 `docs/zh/reports/S93-local-studio-dogfood-20261015.md`。参考现有模型驱动单循环、OpenCode/Claude Code/Codex-rs 的 model→tool→observation 机制与 ADR-0016；只借鉴控制边界，不复制实现。

## 本刀范围

- 用脱敏的结构证据分清三种情况：provider 没给合法 JSON；JSON 有工具调用却被解析器丢弃；合法 JSON 本身只有叙述。只记录形状、字段类型、工具名和判定，不保存原始内容或密钥。
- 针对证实的真实原因修最小边界，保持模型决定动作、工具网关负责权限和写作用域；不让 harness 从叙述猜工具动作。
- 补确定性回归，重跑隔离小任务的 Studio 主路径，核对改动、pytest、Review/Accept。若 provider 仍不发工具调用，保留 blocked 并记录下一证据，不冒充通过。

## 验收与边界

- 修复前有失败复现，修复后同一路径至少出现真实工具调用，最终结果按运行证据报告；若仍失败，指明具体阻塞步骤。
- 运行针对性 pytest、Studio smoke 和文档契约；不碰既有未跟踪验证目录，不读取或提交密钥值，不为此打开新编排 Wave 或弱化权限门。
