# S99 — 不同任务形状的本地 Beta 主路径实跑

## 触发与参考

`研发总计划.md` §16.2 下一项与 `架构设计.md` §10 要求用 3–5 个真实 Beta 任务校准成功率、恢复和体验。已有 S93/S94 的 `small_code_change` 实跑；本刀从 `benchmarks/beta_user_tasks.json` 选择不同形状的 `doc_update`，必要时再试静态网页。参考 OpenCode/Claude Code/Codex 的共同机制是用户给目标后在同一会话看到真实工具、产物和验证证据，失败能继续；只吸收这条主路径，不复制实现。

## 本刀范围与判据

- 在隔离工作区使用本机已有模型路由、Studio 用户入口提交 Goal；不读取或输出密钥，不将临时工作区和 provider 路由写入 Git。
- 记录任务形状、开始到首个真实工具动作、总耗时、最长无反馈、工具/验证/文件事实、会话结果与独立核验；按通过/失败/未运行区分。
- 遇到可复现的真实产品阻碍，只做对应最小修复并加行为回归；没有阻碍就仅登记证据并继续下一样本，不为了填切片造功能。
- 保持 G12/G13/G16/G19 和新编排 Wave 的证据门。已存在的未跟踪验证目录不纳入提交。

## 验收

S99 报告提供可复核的本地证据路径与主路径结论；若改代码，先复现再做最小修复、跑定向测试与 Studio smoke。四份 ACTIVE_SLICE 指针同步，文档契约通过。远端 keyed nightly 未配置时保留 `NOT RUN`。
