# S101 — 静态网页任务的真实 Beta 主路径

## 触发与参考

`研发总计划.md` §16.2 第 13 项与 `架构设计.md` §10 要求继续用不同任务形状做真实 Beta 试跑。S99 已覆盖文档更新，S100 已收紧模型与命令网关边界。本刀选择 `benchmarks/beta_user_tasks.json` 的 `static_landing_page`。参考 OpenCode、Claude Code、Codex 的共同路径：环境事实交给模型，工具执行和错误作为观察回灌，以真实产物和独立核验决定完成；不按模型名称堆命令特例。

## 范围与停止条件

- 在仓库外隔离工作区使用本机已配置路由，从用户 Goal 入口生成 HTML/CSS；不读取、输出或提交 provider key、路由文件、临时工作区。
- 记录路由可用性、模型/工具次数、耗时、命令失败与自修、验证记录、最终状态；浏览器实际打开并检查网页及窄屏。不把无可执行测试的页面称为自动化测试通过。
- 若出现可复现的产品阻碍，保存证据，做最小工程修复和行为回归；若无阻碍，仅登记真实样本，不造功能。
- 跨 OS、跨 provider 是采样目标；只有真实跑到才计入样本，不能用 CI 的无 key 单测或配置存在替代。
- 现有未跟踪验证目录保持原状，不入库。G12/G13/G16/G19 仍由真实 friction 决定是否开刀。

## 验收

产物在隔离工作区存在，浏览器可打开；独立检查内容、布局和链接；记录 Review→Accept 或明确受阻状态。相关测试和文档契约通过，四份 ACTIVE_SLICE 指针同步。远端 keyed proof 缺 key 时保持 `NOT RUN`。
