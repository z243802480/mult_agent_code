# S102 — Linux 跨文件修复真实任务

## 来源与参考

承接研发总计划 §16.2 第 14 项。S101 已有 Windows/Linux 静态页验收，下一任务形状是跨文件 Python 修复。沿用 Codex/Claude Code/OpenCode 的通用机制原则：模型读取项目与失败观察，自行选择工具和改动；权限、schema、预算和证据由 harness 约束，不按 provider 或题目写补丁。

## 范围

- WSL 隔离工作区构造 money.py/report.py 两层缺陷和只读既有测试：金额十进制解析、精确累加、空集合与非法输入。
- 从普通 goal 入口跑修复，先记录缺陷基线，再独立复测并核对源码改动、模型/工具账本和 Review→Accept。
- 尝试本机已配置的独立 provider；失败保留真实结果，无法调用不冒充对照成功。凭据不复制、不输出、不入库。
- 工作区已有 smoke 未提交改动与未跟踪目录保持原状；只在可复现产品阻碍出现时做最小通用工程修复。

## 验收与停止条件

原始失败测试在未改测试前提下转绿；独立边界值检查通过；记录实际模型 provider、工具失败及最终状态。Review→Accept 成功或如实标受阻；文档契约通过，四份 ACTIVE 指针一致。不凭单样本推算成功率。GLM 额度不足时不反复消耗重试，不改变既有配置绕过额度。

## 用户追加：代码质量（2026-11-10）

收敛 Review/CorrectnessEval 重复的终轮证据筛选与分类逻辑；区分缺少旧版证据和明确空终轮，防止历史成功覆盖当前未验证状态。覆盖 discarded、active、未知/缺失 task id 与只读回查边界，保留独立 rerun 语义。仅改本刀相关模块，不顺手重构受锁能力。

## 用户追加：诊断项收口

纠正文档中已被后续授权替代的默认策略和技术栈；补齐执行模型可见的仓库事实与 diff 工具参数，提示按证据停止重复验证。运行新的较大多文件样本和 Studio 会话续作检查，明确真模型/合成测试的区别。当前 provider 额度不足及冻结能力保持诚实待办，不虚构验收；整理当前代码并完成本地检查。
