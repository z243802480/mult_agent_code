# 文档体系总览

本页是中文文档的入口说明。目标不是堆更多规则，而是像 Claude Code 这类成熟产品一样，把“主路由、证据、路线、报告”分开，避免同一件事在不同文档里说成不同版本。

## 1. 优先级

1. [AGENTS.md](../../AGENTS.md)
2. [研发总计划.md](./研发总计划.md)
3. [项目驾驶舱.md](./项目驾驶舱.md)
4. [当前状态与路线.md](./当前状态与路线.md)
5. [开发指南.md](./开发指南.md)
6. [验证试运行手册.md](./验证试运行手册.md)
7. [reports/](./reports/)

## 2. 职责边界

- `研发总计划.md`：长期总计划、当前 phase、slice、禁止事项。
- `项目驾驶舱.md`：一页式进度视图，回答当前完成度、风险和下一步；可由 `scripts/write_project_cockpit.py` 重建。
- `当前状态与路线.md`：当前可执行事实、最新路线判断、下一步建议。
- `开发指南.md`：开发和验证的操作手册，偏命令和环境。
- `验证试运行手册.md`：真实 provider smoke / matrix / evidence 口径。
- `reports/`：签字、里程碑和历史结果。

## 3. 冲突处理

- 以最新的 `当前状态与路线.md` 为准。
- 当 `reports/` 和主文档冲突时，优先主文档，但历史报告保留作证据。
- 当验证手册和最新 matrix 结果冲突时，以最新 matrix summary 为准。
- `tool_use`、fast path、context slimming 这类优化只在有最新证据时写成主结论，否则必须写成灰度或实验。

## 4. 路线原则

- 主路径要短，先验证，再推广。
- 不为单个异常 case 继续堆实现分支。
- 不把一次灰度的好结果写成长期默认。
- 所有结论都要能回到 `model_calls.jsonl`、`final_report_summary.json`、`matrix_summary.json` 或报告正文。

## 5. 当前结论

- `doc_update`、`single_file_bugfix`、`context_maintenance` 仍是固定滚动小灰度子集。
- `tool_use` 运输目前只算灰度试行，不是稳定默认结论。
- 任何“更像 CC”的做法，优先体现在主路径清晰、证据可读、错误可恢复，而不是新增一堆旁路条件。
