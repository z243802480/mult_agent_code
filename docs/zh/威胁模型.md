# 威胁模型

本文档记录 Asteria Runtime OS 的正式威胁模型，覆盖插件系统、MCP adapter、诊断导出、候选工作区 promotion、Workspace/全局配置边界和全自动权限模式等高风险能力区域。

## 1. 插件系统

### 1.1 攻击面

- **恶意插件执行任意代码**：插件 handler 在运行时执行，如果缺乏沙箱隔离，可以访问文件系统、网络和环境变量。
- **插件订阅未授权 hook**：插件订阅了不在 `allowed_hook_names` 中的 hook，导致数据泄露或意外副作用。
- **插件读取敏感数据**：插件 hook 接收到包含 API key、token 或其他凭证的事件数据。

### 1.2 控制措施

- **Manifest 校验**：所有插件必须提供 `plugin_manifest.schema.json` 合规的 manifest，包含权限声明。
- **Hook 白名单**：插件只能订阅 `allowed_hook_names` 内的 hook，超出范围自动 blocked。
- **数据脱敏**：`redacted_data_keys` 在传递给插件前自动脱敏匹配的字段。
- **执行开关**：`hooks.plugins_enabled` 默认 `false`，未启用时插件只能被校验和报告，不能注册 handler。
- **Handler 超时**：`handler_timeout_ms` 限制单次 hook 执行时间。
- **Blocked manifest 阻断 release**：任何 blocked 状态的插件直接阻断 release 阶段。

### 1.3 剩余风险

- 当前插件 handler 在主进程内执行，未实现进程隔离。后续需引入子进程 / WASM 沙箱。
- 插件可以声明低权限但实际执行高权限操作（尚无运行时权限强制）。

## 2. MCP Adapter

### 2.1 攻击面

- **恶意 MCP 服务端注入有害响应**：MCP server 返回的工具调用结果可能包含指令注入或数据泄露。
- **网络中间人攻击**：MCP 通信被拦截或篡改。
- **未授权的外部服务访问**：运行时连接到未经审核的 MCP server。

### 2.2 控制措施

- **网络默认关闭**：`permissions.allow_network` 默认 `false`。
- **MCP 地址白名单**：只允许连接预配置的 MCP 端点。
- **工具调用结果校验**：消费方必须对 MCP 响应做 schema 校验。

### 2.3 剩余风险

- MCP adapter 尚在设计阶段（ADR 待建），实际威胁在实现后需复评。
- 未实现 TLS pinning 或签名验证。

## 3. 诊断导出

### 3.1 攻击面

- **敏感数据泄露**：诊断包包含 API key、源码片段、环境变量、内部路径等敏感信息。
- **诊断包被中间人截获**：用户将诊断包发送给维护者时可能被截获。

### 3.2 控制措施

- **默认只读和脱敏**：`doctor --export` 输出前自动脱敏 API key、`secret`/`token`/`password` 等字段和 protected paths 内容。
- **不包含源码全文**：诊断包只包含元数据、配置和结构化证据，不包含用户项目源码。
- **Workspace-local 导出**：诊断包默认只导出当前 Workspace 下的 `.asteria/` 运行证据摘要，不导出全局用户目录中的 route/key/account/cache/logs，也不导出其他 Workspace 的 session 或 evidence。
- **审计日志**：每次导出操作记录在审计日志中。

### 3.3 剩余风险

- 脱敏规则可能无法覆盖所有自定义字段名。
- 诊断包未加密传输，依赖用户自行保护。

## 4. 候选工作区 Promotion

### 4.1 攻击面

- **恶意 candidate 覆盖主工作区文件**：通过 promotion 将有害变更合并到主工作区。
- **失败 candidate 泄露敏感数据**：失败的候选工作区残留敏感文件。
- **Race condition 导致数据损坏**：并发 promotion 导致文件覆盖。

### 4.2 控制措施

- **Merge gate 强制检查**：所有 promotion 必须通过 MergeGate，检查 write scope、changed files 和 verification results。
- **候选工作区隔离**：失败的候选工作区使用 `discard()` 完全清理，主工作区不受影响。
- **Promotion queue 状态集合**：明确 queued/pending/approved/blocked/failed/discarded 等状态和转换规则；它只约束候选合并队列，不代表把大模型工作循环脚本化。
- **Release 阻断**：`promotion_release_risks` 检查未解决的 promotion 并阻断 release_ready。
- **Golden trace 契约保证**：`test_failed_candidate_does_not_pollute_main_workspace` 防止隔离行为回归。

### 4.3 剩余风险

- Git worktree 隔离尚未完全实现，当前使用临时目录复制。
- 无法阻止具有合法 write scope 的恶意变更（需人工审批）。

## 5. Workspace 与全局配置边界

### 5.1 攻击面

- **跨 Workspace 数据污染**：一个项目的 session、run evidence、artifact 或 Git 状态被写入另一个 Workspace。
- **全局配置泄露**：模型 route、API key、账号引用、token 或 UI 缓存被误写进项目 evidence、诊断包或提交记录。
- **错误 Workspace 执行**：Studio/CLI 没有明确当前 Workspace，导致用户以为在 A 项目执行，实际修改 B 项目。

### 5.2 控制措施

- **Workspace Envelope**：每个 run 必须绑定 `workspace_id`、`root`、`output_root`、`session_id` 和 `run_id`。
- **路径分层**：项目级状态、session、run、evidence 和 artifacts 落在当前 Workspace 的 `.asteria/`；全局用户目录只保存 recent/current workspace、模型路由、账号引用、UI 偏好和缓存。
- **切换确认**：Studio 的 Project/Workspace Switcher 必须让用户看见当前 workspace，并在切换后重新绑定 session、文件视图、Git 状态和运行证据。
- **导出排除**：evidence bundle 和诊断导出默认排除全局用户目录、其他 Workspace、`.git/`、`.env*`、`secrets/`、证书和私钥。

### 5.3 剩余风险

- 用户手动选择错误目录时，runtime 只能通过路径提示、Git 状态和输出范围确认降低风险。
- 全局缓存仍可能包含非敏感但可推断用户行为的信息，后续需要缓存分级和清理策略。

## 6. 全自动权限模式

### 6.1 攻击面

- **模型误判导致连续高风险操作**：`auto` 模式下模型连续执行安装、删除、联网、写入或重构操作，扩大损害范围。
- **提示注入诱导越权**：项目文件、MCP 返回、网页或工具输出诱导模型读取 secrets、删除文件或推送远程。
- **预算与时间失控**：自动循环不断调用模型和工具，没有产出却持续消耗额度。

### 6.2 控制措施

- **硬护栏不随模式取消**：`auto` 仍必须阻断 protected paths、secret 读取、破坏性 shell、全局安装、远程 push、生产部署、预算 hard-stop、Workspace 越界和不可恢复删除。
- **候选工作区和验证优先**：高影响写入应通过 candidate workspace、diff、验证、MergeGate、回滚或等价机制推进。
- **过程可见**：用户侧必须实时看到模型判断、API/模型调用摘要、工具调用、文件变化、验证进展和最终整理；Inspector 保存底层证据。
- **异常收敛**：无产物调用、重复失败、范围扩大、成本接近上限时自动压缩、降级、暂停或进入恢复流程。

### 6.3 剩余风险

- `auto` 的产品体验依赖模型体系化能力和 runtime evidence 质量；在能力画像不足的任务类型上应降级为 `reviewed_auto` 或收紧任务预算。

## 7. 跨领域控制

- 所有高风险能力都需要明确的 policy 开关，不能默认启用。
- Feature flag 和 capability flag 必须同时检查：开关打开但环境不支持时不得启用。
- 发布分级（targeted/core/full_gray_core）决定验证范围，不能跳过。
- 威胁模型覆盖的能力变更时必须同步更新本文档。
