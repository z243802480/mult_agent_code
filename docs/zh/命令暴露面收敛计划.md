# 命令暴露面收敛计划

更新时间：2026-05-19

## 目标

命令收敛的目标是降低 alpha 用户的心智负担，而不是删除专家能力。当前内部命令已经能覆盖开发、灰度、验收和运维；下一步应把用户默认路径和维护者路径分层。

## 分层

### 普通用户主入口

这些命令应该出现在 README、quickstart 和默认帮助路径中：

- `init`：初始化 workspace。
- `run`：创建或继续一个目标闭环。
- `status`：查看当前 session、成本、阻塞和候选状态。
- `resume`：处理决策或暂停后恢复。
- `review`：查看当前 run 的质量评审。
- `accept`：预留产品语义，建议后续定义为“接受当前已验证候选或完成状态”，在语义冻结前不新增别名。

### 灰度/维护入口

这些命令面向 alpha 维护者和灰度试运行：

- `doctor`：本地环境和配置诊断。
- `gate`：阶段化门禁入口。第一版为只读包装，串联 `version`、`package-check`、`doctor` 和 `gate-status`；后续再按阶段加入真实 `real-model-gate` 和 `acceptance-gate` 执行模式。
- `gray`：灰度入口。第一版为 dry-run 包装，串联 `gate-status` 与 `gray-run --dry-run`，用于生成小真实任务计划或解释 route guidance / promotion / plugin / 环境阻断原因；后续再加入完整 `real-model-acceptance --suite gray` 与正式 `gray-run` 执行模式。
- `release`：预留为发布入口，后续包装完整 `ruff/mypy/pytest/package-check/acceptance-gate` 流程。

### 专家/内部入口

这些命令保留，但不应成为普通用户完成任务的必经概念：

- `model-check`
- `real-model-smoke`
- `real-model-gate`
- `real-model-acceptance`
- `acceptance`
- `acceptance-gate`
- `capability-report`
- `promotions`
- `plugins`
- `daily-*` / `long-run-*`
- `research` / `brainstorm` / `replan` / `debug` / `compact` / `handoff`

## 近期实现顺序

1. 文档先收敛：README 和灰度 runbook 只展示主入口与灰度/维护入口，把专家命令移到“排障和开发者参考”。
2. 再新增包装命令：只读 `gate` 和 dry-run `gray` 已进入第一版，避免先改变候选写入体验；下一步是补阶段化执行模式和更清晰的失败收集报告。
3. 最后定义 `accept`：必须先消除与 `acceptance`、`promotions approve` 的语义冲突。

## 不立即新增别名的原因

- `accept` 容易被理解为 acceptance gate，也可能被理解为候选 promotion approve。
- `gray` 如果直接等价于 `gray-run`，会隐藏真实 provider gate 与 gray suite 的前置关系。
- `release` 如果只等价于 `acceptance-gate`，会误导用户以为发布检查已覆盖 lint、typecheck、package 和真实 route。

因此下一步应先实现包装命令的阶段化输出，再把旧专家命令逐步移到高级帮助。
