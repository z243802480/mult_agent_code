## 1. 产品 North Star（10 年方向）

```text
Harness 优先的通用长任务智能体生产力系统
```

**用户价值**：给定目标 → 核心 Agent Loop 完成 → 意图识别 → 按需 Plan → 分层 Tool/MCP/Skill/Subagent → 过程化输出 → 多类型结果（代码/文档/原型/创意等）→ 总结 → 用户续作 → 循环。

**差异化（相对 Claude Code / Codex / OpenCode 照抄）**：

- 本地优先、`.asteria/` 可审计证据链
- candidate workspace + promotion + merge gate
- 多 provider 路由与成本护栏
- **North Star 长目标**（OpenCode utw 思路）：远端目标，跨 run 主动靠近
- **蜂群委托 + sandbox 并行**（Phase 4+）：调研→架构→开发→测试→迭代
- **一人公司底座**：同一 harness 支撑未来批量 demo 产品

**参考哲学（强制）**：

```text
学机制，不抄形态；学结论，不抄专有实现。
对标 OpenCode / Claude Code / Codex-rs，不闭门造轮子。
```

**非目标（任何智能体不得突破）**：

- 无限制 agent 聊天室
- 无策略批准的破坏性 shell / 生产部署 / 远程 push
- 单一 model provider 依赖
- 跳过 schema 验证的持久化对象
- 在 harness 未稳前做复杂 dashboard / gate 主屏
- 复制外部产品专有实现

## 6. 代码 Triage 锁（任何智能体不得违反）

### KEEP_CORE — 禁止删除

`run_command`, `execute_command`, `plan`, `chat`, `status`, `review`, `accept`, `debug`, `init`, `resume`, `sessions`, `user_progress_logger`, `runtime_progress`, agent_loop_*, candidate/merge/promotion, `studio/server.mjs`, `Thread`, `Composer`, `intent-router`, schemas/, 核心 tests.

### KEEP_PLACEHOLDER — 禁止扩展实现（Phase 0–2）

`disjoint_write_gate`, `sandbox_backend`, subagent 写并行, MemoryAgent 等 Deferred 角色, legacy `event_logger` fallback.

### HIDE_NOT_DELETE — 从用户 help 隐藏，禁止删除

daily/weekly/roadmap, ops-signal, gate/acceptance/validation/real-model-*, evidence-bundle, capability-report, execute/replan/compact（高级入口）.

### MERGE_OR_TRIM — Phase 1b 允许

| 对象 | 动作 |
|------|------|
| `runs_command.py` | DELETE |
| `validation` 命令 | 合并进 `validation-run --dry-run` |
| `new` 命令 | 合并进 `plan` 或弃用 |
| CLI legacy 别名 | 减注册，保留主名 |
| Studio 冒充完成 | 删行为 |
| `plan-output-smoke.mjs` | 合并进 chat-fallback |

### DO_NOT_TOUCH — Phase 0–2 禁止重构

`execute_command.py`, `run_command.py`, `gate_status_command.py`, acceptance/real_model 栈. **仅允许追加 user_progress 写入点。**

```mermaid
flowchart TB
    User[用户 Goal/Plan/Ask]
```

## 11. 智能体强制操作规程

**任何智能体在开始工作前必须**：

1. 读 `AGENTS.md` + 本文 + `ACTIVE_SLICE`  
2. 确认当前 Phase；**禁止**做 Deferred 项（North Star、蜂群、12 Agent 新类）除非 todo 明确  
3. 若改代码：查 §6 Triage；**禁止** DO_NOT_TOUCH 重构  
4. 若新 Slice：先写 `reference_briefs/Sn.md`  
5. 会话结束：跑相关 pytest/smoke；更新 ACTIVE_SLICE；不过闸门不开下一 Slice  

**禁止的 prompt 模式**：

- 「帮我把 Asteria 做好」  
- 「顺便重构 execute/run」  
- 「加一个 maintainer 命令」  
- 无 brief 造新抽象  

**推荐 prompt 模板**：

```text
执行：Vibe Slice S3 | Phase 1 | todo: progress-contract
Triage: KEEP_CORE only | DO_NOT_TOUCH execute/run
Reference: benchmarks/reference_briefs/S3-verify.md 已读
Red: <命令>  Green: <命令>
禁止: North Star, 新命令, gate 主屏, 冒充完成
```
