## 核实结论

重新读取旧三副本审计：同一登记方法和 Review 自选方法在原坏件退出 0，在符合原要求的有效修正退出 1，错误输出也拒绝。它们覆盖部分行为、固化了实现锚点，既遗漏原要求又排斥有效替代。旧审计、方法 SHA、失败和有效替代不回写；本轮仅复制并核对已有审计记录，**没有再次执行这些旧命令或重采旧题模型**。

回代码与真实网关控制确认：普通断言失败不会被 `ReviewTools.finish` 自动当成永久的硬边界错误；失败观察进入下一请求后，评审可以选择新的有效检查并给出 pass，也可以在新检查仍失败时给出 fail。权限拒绝、超时、复制/源输入变化的既有守卫保持。不能将旧坏件漏检归因于“失败被固化”或原要求没进入输入；本轮未发现支持这两种归因的生产缺口，因此没有强造运行时补丁。

新增非生产夹具 [conditional_aggregation.py](../../../benchmarks/review_cases/conditional_aggregation.py) 和 [工程控制](../../../tests/unit/test_review_conditional_coverage.py)，作为可持续回归材料。沿用 [OpenAI 评估实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices) 中任务相关、边界/反向样本和人工校准的评估思路；没有接入外部 eval 服务或增加依赖。

## 评估目标与公平性

自然请求要求 `aggregate(rows, *, region=None)`：先确认 exact-bool enabled，disabled 行在访问其他字段之前跳过；enabled 行先确认 region，按过滤条件跳过其他区域后才访问/校验 sku 与 qty。还要求严格数量类型、首次顺序聚合、拼写保持、一遍输入、新输出对象、输入不变、错误处理、空集合和关键词 API。只允许修改 `aggregate.py`。

四份实现共享同一个自然请求、指导、两项原项目测试和检查入口；缺陷一提前校验 disabled 行的 region，缺陷二提前校验被区域过滤掉的载荷。合格与有效替代按 API 行为接受，不按源码布局、helper 名称、导入、措辞或格式要求判断。外部 oracle 的 22 项判据不进入模型输入；项目 2 项浅测试四个版本都通过，不能据此签全面覆盖。

冻结前发现初版合格夹具提前读取了未入选行的字段，初版 oracle 只检查返回/异常而未观察访问。已纠正夹具并加入字典访问观察，合格与有效替代均通过 22 项；两个坏件各自被三个对应条件判据拒收。没有改原始请求来迁就实现。这也是本轮评估质量修正，不冒充生产修复。

控制场每场通过普通网关进行 1 次写入和 1 次项目检查，共 8 条 controller 种子，非模型自主开发。随后每场只做一次标准 Review（原生最多 8 轮 / 120 秒）；四控制不 Accept。新自然目标单独运行一次（32 轮 / 外部 900 秒），独立与范围合格才做正式 Review / fresh Accept，没有在途喂答案、清理或代批。

## 自然目标与方法修订

一次新 Goal **226.47 秒、16 真模型**，自主形成实现与验证两项任务，均 done。原生 completed/auto-finalize 后，外部 22 项行为判据、项目原两测及范围检查合格；只修改 `aggregate.py`、无新增 authored 文件，两项 pyc 保留。两次 list_files 越界读 checks 前置拒绝且不收费，模型自行调整，未放宽读取范围或代批。

随后正式 Review **20.47 秒、4 真模型、3 次检查**，pass 1.0；fresh Accept **0.40 秒、accepted=true**。三次检查分别为项目入口退出 0、自拟条件检查退出 1、修正后的条件检查退出 0。首次自拟断言错误地要求把 `" A "` 与 `"A"` 合并；实际输出保留二者差别，与原要求一致。评审收到失败观察后修订了检查，接受原始拼写保持的有效实现，**没有修改交付文件或原始要求**。这是 Review 临时检查的自主修订，不是 `revise_verification` 登记方法 API 调用，不能混记。

正式 Review 没有执行同一个外部 22 项 oracle；独立验收与评审自建检查分开。普通失败后形成有效新判断的机制既有确定性控制，也有本次真实流程证据，不再据“曾有退出 1”自动推断必须改变守卫。
