## 问题与实现

S118 的早期专用测试失败，后来的不同复合 shell 命令虽然成功，也不能确定覆盖了同身份验证。原命令折叠的保守语义正确，缺的是在模型尝试收尾时明确反馈这个事实。原 pre_final 钩子只检查交付物存在，故任务先退出内循环，再被外层契约拒绝和重规划。

现在 model_driven_turn 把已有观察的 tuple 引用交给 pre_final；不复制输出正文、不写新持久化 schema。Execute 收尾反馈与最终验收复用同一个验证结果选择函数，沿用精确 requested_command 优先、同命令取最新和既有噪声处理口径。未声明固定检查的任务若仍有命令的最新结果失败，会收到精确身份与事实提示，由模型决定如何处理。不同命令或复合命令不会覆盖原失败。

每个新的失败观察只提示一次；模型不处理、继续声称结束时，不重复同一提示空转，仍交最终契约及现有外层策略判定。声明检查保留既有后置验证，不重复新建执行责任。进度和钩子事件记录未闭合命令，主线程说明“验证未通过，继续处理”；不向用户展示模型提示词。权限、预算/迭代保险丝和工具选择能力保持。

第二个问题是修复任务可能面对已经修好的文件，但仍被要求制造新 diff。旧规则看到 verification failed 一律禁止 verified-noop；即使原失败命令的新结果已经通过，也要再失败一轮才进入 verify-first。

新窄窗口仅在来源契约记录了非空 changed_files、所有失败验证都有精确命令身份、没有未知违例时启用：把**全部原失败命令和真正声明的原检查**钉为现有 planner_task 验证契约。新鲜同身份结果全部通过才允许零新增改动收尾；原命令仍失败、只运行其他绿色命令、缺身份、来源无改动或未知违例均不能通过。重验不会把历史 `validation_commands` 中未声明的自然语言说明提升为可执行命令。旧未验证/未改动窗口保持原语义；新增的失败重验窗口不能用任意绿色命令替代。

没有按模型、provider、测试文件名或 stderr 关键词放行；没有添加命令复测次数硬门、自动语义解析或新的修复状态机。对 DO_NOT_TOUCH 的 execute 仅改脊梁接线与共用验收口径，不改 Run 编排。

## 防绕过与回归

新增四项真实 Execute/Replan + ToolRegistry 确定性集成：

- A 失败，文件已修复、B 成功后尝试结束：模型收到 A 的身份反馈，同一 task 内重验 A 成功后完成。
- 模型拒绝处理反馈：只提示一次，正常 blocked，不无限续跑、不制造新 task。
- 有来源改动且当前文件正确：修复不写文件，原 A 被强制验证并通过后完成，原文件字节保持，累计工具计量递增。
- 当前文件仍错：B 绿色也挡不住被钉住的 A，实际执行 A 失败后仍 blocked。

单元另覆盖未知违例、无/空改动证据、缺命令身份、混入无身份失败、原真实声明检查保留、原 requested_command 优先、旧 prose 不执行，以及 pre_final 集合没有可变 list 别名。原“verified-noop 标志必须 false”测试更新为更强的实际执行断言：错误的 answer=41 仍无法通过原 answer=42 验证，原产物不变。未移除防绕过场景。

## session 分支与边界

已核对：内层是模型驱动的同任务循环；若最终契约仍失败，RunCommand 外层依然根据已授权的 auto_replan_goal 权限策略回退，未用 profile.use_replan_lineage 关闭此层。本刀既不关闭自主恢复，也不声称以后不会重规划；目标是让内层先得到可操作的事实，并让严格重验不再强制无用 diff。
