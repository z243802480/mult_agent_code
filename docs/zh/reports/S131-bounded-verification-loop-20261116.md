- **验证前指导**：共享指导要求先核对所选输入、数量、覆盖与准备/执行副作用，有不确定性时先收窄检查。选择检查及修正方法仍由模型完成；运行时不解析语言、文档格式或具体命令来替模型选择。
- **工具后事实**：真实观察进入执行循环后触发 `post_tool_observation`。复用现有 `workspace_changes` 和 `edit_boundary_allows`，包括失败命令产生的创建、修改、删除；附实际工具调用 ID。每个新事件即时提示一次，收尾前再提醒一次。正文最多 16 条并明示省略数，完整观察仍保留；扫描未知不变成“无变化”。Studio/CLI 的进度证据同时明确出现范围事件，不虚构“已请求批准”。
- **主动授权**：`request_execution_permission` 只接受当前任务已经具备的 `run_command` / `run_tests` 能力及具体完整参数、原因。它复用 `execution_policy_approval`，在执行前暂停整批工具，复用 pending 请求，再走真实 Decide/Resume。此时尚无工具执行，不伪造观察或收费；恢复后查询实际决定才是一条正常状态工具记录。
- **授权边界**：批准按任务、工具和完整参数匹配；拒绝不会变成放行，也不会重复弹同一个请求。查询授权本身不执行命令，不改变全局策略或 Goal 编辑上限。拒绝后的续作沿用现有 skip 语义，不声称模型一定自动换方法。原预算、迭代保险和完成/验收边界保持。

本刀没有自动清理或事件冲销机制：即使后来获得某条执行命令的批准，也不等于旧范围事件已经解决或旧任务已经验收。原失败数据不得因此删除。没有 OS 写隔离、格式专用检查或 provider 补丁。

机制参考：[Claude Code hooks](https://code.claude.com/docs/en/hooks) 的工具后反馈与停止边界；[OpenAI 安全执行](https://openai.com/index/running-codex-safely/) 对审批和执行约束的区分。参考公开设计，不宣称实现相同内部机制。
