# S130 — 模型自拟验证方法的证据化修订

2026-11-12；[参考 brief](../../../benchmarks/reference_briefs/S130-verification-method-revision.md)。当前完成机制实现与确定性验证，全套回归和源码 CI 收口后补记。

## 问题与实现

S127/S128 联合真跑中，Planner 的具体检查方法自身有语法错误。模型执行另一种正确方法后，完成闸仍按原声明命令拒绝，重规划继续继承。原拒收合理地保留了失败，但缺少区分“上层要求”和“模型提出的方法”的修订路径。原联合目标仍为拒收，不改其日志、审批或3个DB副产物。

规划器现在为自己提出的方法生成来源记录，绑定 GoalSpec、project.json 配置命令和完整 AGENTS.md 的摘要。模型不能通过原始计划 JSON 自报可修改授权。上层文本中的原样检查、包含已配置检查的命令包装均保守保护；来源缺失、权威变化、指导不可完整读取或超256Ki字符均不可自动修订。授权判断独立读全指导，模型提示仍使用既有4k摘要，不把缺失的尾部当成没有要求。

新增模型工具 `revise_verification`，仅处理运行时绑定的当前 in_progress 任务。它要求同任务原方法的实际非零失败、之后替代方法的实际零退出成功、未过期且 stat 未观察到工作区变动的证据，以及模型给出的原因和覆盖说明。前置拒绝、未执行、预期非零、其他任务、旧成功、有副作用或扫描不可用均不能作为替代证据。工具不执行命令，也不改 GoalSpec、acceptance、完成要求或文件权限。

修订原子写入现有 TaskBoard（task_plan.json），使用根目录和包内一致的 Task schema 校验，记录原/替代命令、原因、覆盖说明、两条观察ID和时间；旧账本保持。工具网关重新读取已验证的持久字段，立即同步本轮完成闸。重规划继承来源与历史；采用上层检查作替代也不会授予它未来可修改的权限。JSON 与 native 工具面均接通，经过既有权限、工具调用身份和预算路径，按 state 工具计量。只读任务可修订方法元数据，但不会获得工件写权限。

## 验证

定向回归覆盖来源伪造/缺失、带引号用户检查、配置检查包装、完整指导尾部、权威变化、证据顺序/任务/实际退出状态/新鲜度/副作用、预算拒绝、保留原失败、当前执行同步、只读恢复、重规划历史和双工具传输。

真实 PlanCommand → 模型规划归一化 → ExecuteCommand → 实际 shell/file 工具 → 完成闸的确定性集成控制：未显式修订仍拒收；有来源且证据充分的修订可完成；随后把工件改坏则重新拒收；长指导摘录不扩大模型提示且授权仍使用完整内容。模型选择由夹具提供，不能标为真 provider 或自发修复证据。

当前已验：WSL 相关110 passed；Ruff（src/tests/scripts）净，mypy ratchet 无新增（60条既有，18条已不再报告，未改基线）；五项离线基准通过。

首次完整回归1891 passed、5 failed：新增工具暴露两处旧清单夹具，以及生产验证矩阵硬编码旧工具清单造成的3项连带失败。矩阵现从真实默认注册表取工具，并补“缺后端仍拒收”的负控；清单断言加入新工具，原就绪标准不变。最终完整回归、此修复的WSL定向与源码CI待收口。

## 诚实边界与下一步

零退出、stat 无变动和覆盖说明不构成任意程序的语义等价证明。要求与工件覆盖仍需模型解释和实际验收，不把修订工具的成功算成一次验证通过。指导中非原样表达的语义要求不能靠字符串守卫自动理解；GoalSpec/acceptance 保留，修订不能作为降要求的理由。

旧无来源任务不自动补授权，自动 Replan 只继承既有事实，不能凭失败临时发明来源。它们需要重新形成有可信来源的计划；本切片不会把旧 S127/S128 样本翻成成功。

新真模型目标、正式 Review/Accept 与 keyed proof **NOT RUN**。下一步用冻结源码和独立验收器执行一个新的有界目标，观察模型是否自行收敛并审计方法修订、文件范围、唯一调用身份和计量；不注入评估器答案、不重复试到绿。小时级自治和独立 provider 泛化仍未证明。
