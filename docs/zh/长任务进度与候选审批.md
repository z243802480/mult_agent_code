# 长任务进度与候选审批

更新时间：2026-05-19

## 长任务 heartbeat

真实 provider 的 `real-model-gate`、`real-model-acceptance` 和 `real-model-smoke` 链路会在等待子进程时输出低噪声 heartbeat，避免长时间无反馈。

- 默认间隔：`ASTERIA_HEARTBEAT_SECONDS=30`
- 禁用方式：`ASTERIA_HEARTBEAT_SECONDS=0`
- 输出位置：stderr
- 输出内容：当前任务、elapsed、remaining、run id、run status、model/tool call 数、最近 runtime event、最近模型 route/provider/streaming 摘要

heartbeat 只读取 `.asteria/` 中的运行元数据，不输出 prompt、模型正文、API key 或 protected paths 内容。
这里的 `.asteria/` 指当前 Workspace 下的运行目录；全局用户目录中的 route/key/account 配置不属于 heartbeat 数据源。Studio 可以把 heartbeat 和 `user_progress.jsonl` 映射为用户侧过程线，但主线程只展示低噪声判断、进度、工具和验证摘要，原始命令输出进入 Inspector。

## 候选审批策略

`promotion.manual_approval_default` 已经具备完整运行语义。

- `ask_everything`：每次候选 promotion 都进入 `pending_manual_approval`，任务进入 `blocked`，主工作区不被写入，除非用户明确 approve。
- `reviewed_auto`：低风险、写入范围明确、验证通过且未触发 release risk 的候选可以自动 promotion；高风险、跨目录、大范围变更、测试失败、预算异常或策略命中时进入 `pending_manual_approval`。
- `auto`：允许模型主导的自动 promotion，但仍必须通过 MergeGate、write scope、diff、验证、成本/风险检查和回滚策略；protected paths、secrets、破坏性删除、远程 push、生产部署和 Workspace 越界不能因为 `auto` 自动放行。
- `promotion.manual_approval_default=false`：在当前权限模式允许时保持自动 promotion 路径，验证通过后尝试合并到主工作区，并记录 `auto_approved -> promoted`。
- `promotion.manual_approval_default=true`：无论权限模式如何，验证通过后只写入 `pending_manual_approval`，任务进入 `blocked`，主工作区不被写入。
- 人工审批：`asteria promotions approve --promotion-id <id>`
- 拒绝或丢弃：`asteria promotions reject --promotion-id <id>` / `asteria promotions discard --promotion-id <id>`

在 `true` 模式下，candidate workspace 会保留到 operator 明确 approve/reject/discard；release gate 会继续把 unresolved promotion 视为 release blocking risk。
