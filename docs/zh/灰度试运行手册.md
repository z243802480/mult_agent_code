# 灰度试运行手册

本文档定义本地产品包进入小范围灰度试运行前后的固定流程。目标是让系统可安装、可诊断、可暂停、可回滚，而不是直接进入长时间无人值守运行。

## 1. 灰度范围

首轮只开放低风险开发任务：

- 文档更新。
- 小型 CLI 或脚本。
- 多文件小工具。
- 测试修复。
- 受控重构。

暂不开放：

- 生产部署。
- 远程 push。
- 破坏性 shell。
- 读取 protected paths。
- 长时间无限制自动推进。

## 2. 模型路线

当前推荐路线：

```powershell
$env:AGENT_MODEL_STRONG_PROVIDER = "glm"
$env:AGENT_MODEL_STRONG_BASE_URL = "https://open.bigmodel.cn/api/coding/paas/v4"
$env:AGENT_MODEL_STRONG_NAME = "glm-4.7"
$env:AGENT_MODEL_STRONG_API_KEY = "<your glm coding key>"

$env:AGENT_MODEL_MEDIUM_PROVIDER = "minimax"
$env:AGENT_MODEL_MEDIUM_NAME = "MiniMax-M2.7"
$env:AGENT_MODEL_MEDIUM_API_KEY = "<your minimax key>"

$env:AGENT_MODEL_CHEAP_PROVIDER = "fake"
```

`glm-4.7` 用于成本优先灰度，消耗免费 token 额度。额度耗尽、质量不足、真实 core release gate 或最终灰度发布复验时，把 `AGENT_MODEL_STRONG_NAME` 切到 `glm-5.1`。

## 3. 打包前检查

在仓库根目录运行：

```powershell
python -m agent_runtime version --json
python -m agent_runtime package-check --root . --json
ruff check .
mypy src
python -m pytest
```

`package-check` 必须通过。它会检查：

- `pyproject.toml` 项目名和版本。
- build backend。
- `agent` console script。
- runtime `__version__` 与 pyproject version 是否一致。
- 灰度文档是否存在。
- `dist/` 下是否已有 wheel/source artifact。

没有 `dist/` artifact 不阻断代码提交，但阻断正式灰度包交付。当前推荐用仓库脚本构建本地 wheel：

```powershell
python scripts/build_package.py --root . --clean
python -m agent_runtime package-check --root . --json
```

## 4. 发布门槛

灰度前固定顺序：

```powershell
python -m agent_runtime doctor --root . --json
python -m agent_runtime model-check --root . --tier strong
python -m agent_runtime model-check --root . --tier medium
python scripts/real_model_gate.py --summary-json .agent/model/real_model_gate_report.json
python scripts/real_model_acceptance.py --suite gray --summary-json .agent/verification/real_model_acceptance_gray.json
python -m agent_runtime gate-status --root . --json
```

只有 `gate-status --json` 输出：

```json
{
  "rollout_state": "conditional",
  "stage": "ready_for_core_acceptance"
}
```

才进入真实 core acceptance：

```powershell
python scripts/real_model_acceptance.py --suite core --summary-json .agent/verification/real_model_acceptance_core.json
python -m agent_runtime acceptance-gate --root . --suite core --min-scenarios 11 --min-capabilities 11
python -m agent_runtime gate-status --root . --json
```

`rollout_state=release_ready` 才允许进入小范围真实任务灰度。

## 5. 首个真实任务

每个灰度任务都必须写清：

- Definition of Done。
- 写入范围。
- 验证命令。
- 模型和工具预算。
- 回滚方式。

推荐命令形态：

```powershell
python -m agent_runtime /run "<small scoped goal>" --root . --max-iterations 3 --max-tasks-per-iteration 1 --no-research
python -m agent_runtime status --root . --json
python -m agent_runtime review --root .
```

如果出现 blocked task：

```powershell
python -m agent_runtime debug --root . --max-repairs 1
python -m agent_runtime replan --root . --max-items 1
```

不要在灰度期无限增加 repair/replan 次数。

## 6. 故障收集

出现失败时先收集：

```powershell
python -m agent_runtime version --json
python -m agent_runtime status --root . --json
python -m agent_runtime doctor --root . --json
python -m agent_runtime gate-status --root . --json
python -m agent_runtime capability-report --root .
```

保留以下运行态证据，但不要提交真实 API key 或完整敏感 transcript：

- `.agent/model/latest_failure.json`
- `.agent/model/real_model_gate_report.json`
- `.agent/verification/real_model_acceptance_gray.json`
- `.agent/verification/real_model_acceptance_core.json`
- `.agent/acceptance/acceptance_report.json`
- `.agent/runs/<run-id>/final_report.md`
- `.agent/runs/<run-id>/task_execution_evidence.jsonl`
- `.agent/runs/<run-id>/worker_results.jsonl`

## 7. 暂停和恢复

长任务暂停、上下文压缩或交接前运行：

```powershell
python -m agent_runtime compact --root .
python -m agent_runtime handoff --root . --to FutureRun
```

恢复前先看：

```powershell
python -m agent_runtime sessions --root . --context
python -m agent_runtime status --root . --json
```

## 8. 回滚和退出标准

出现以下情况应暂停灰度：

- `gate-status` 不是 `conditional` 或 `release_ready`。
- provider response 反复不符合 schema。
- 预算频繁 `near_limit` 或 hard stop。
- merge gate 出现误 promotion 风险。
- protected path 风险。
- session 无法恢复。
- 报告无法解释完成项、阻塞项和成本。

回滚方式：

- 未 promotion 的候选工作区直接丢弃。
- 已进入 git 分支的候选改动用普通 git revert 或新修复提交处理。
- 不使用 destructive shell 清理工作区。
- 先生成 handoff/context snapshot，再处理失败证据。
