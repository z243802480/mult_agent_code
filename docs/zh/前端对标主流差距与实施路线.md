## 0. 继承的硬约束（原路线 §1/§2，仍然全部有效）

1. **主区内容丰富**——plan/工具/diff/进度端到主区，不止流式文本。
2. **紧凑·高级·去框化神圣**——richness 靠排版/字重/缩进/语义色/默认折叠，不靠新卡片背景；响亮色只留给需人决策的（diff/权限/错误）。
3. **绝对诚实**——无真事件不渲染；估算必标 `est.`；无定价不显 `$`；不在终止事件前显绿"done"；压缩/截断显式告知。
4. **长任务不崩**——窗口化、seq 游标幂等重连、磁盘 JSONL 永远是真源。
5. **派生而非杜撰**——新 UI 一律从运行时已流出的事件派生；无数据渲染空而非占位。
6. **抄主流交互语义，不自创设计结构**（习惯迁移成本）；**独有能力**（证据链/promotion/验证矩阵）**藏进 Inspector**，不稀释主线程。

## 4. 实施思路（observed_pattern → 落点 → 思路 → 验收 → 不抄什么）

### G1 通知体系（S）
- **模式**：Claude Code"会话完成任务且你不在看该会话"才发 OS 通知；Crush 仅终端失焦时提醒；Devin favicon 绿/橙点；OpenCode attention（通知+音效，问题/权限/完成三类）。
- **落点**：新 `hooks/useNotifications.ts` + `SettingsPanel` 开关分区；favicon 用 canvas 重绘。
- **思路**：触发源=已有 settled 信号（completed/failed）与 waiting/permission_request 事件（F1·1.2.54 已诚实化）；规则=`document.hidden || 非当前会话` 才发 `Notification`（localhost 是 secure context，API 直接可用）；favicon 点三态（运行=蓝、待决策/waiting=橙、失败=红）；声音默认关。首次开启走浏览器权限请求，拒绝则诚实降级为 favicon 点。
- **验收**：后台标签页跑 run→完成时收到 OS 通知+favicon 变点；前台盯着看时**不**发；权限请求事件发"需要你决策"；设置可全关。
- **不抄**：移动推送（无云中继，不伪造"离线可达"）。

### G2 常驻 usage ring（S）
- **模式**：Claude Code 模型选择器旁 usage ring，点开看会话上下文占用；VS Code 提示框内建 context indicator。
- **落点**：`Composer` 或 `MissionPaneHeader` 加小环；复用 `readContextUsage` helper 与 ContextPanel 数据。
- **思路**：环显 context 占用百分比（数据已在 cost_report/context 快照事件里）；点击展开既有 ContextPanel；无数据不渲染（派生而非杜撰）；`est.` 照标。
- **验收**：运行中环实时推进；无 cost_report 的会话不显示；点击直达 Inspector 上下文标签。
- **不抄**：订阅额度环（无订阅体系）；美元（无定价，G18 另议）。

### G3 会话状态徽章+归档+过滤（M）——mission control 地基
- **模式**：Claude Code 侧栏按状态/项目过滤+hover 归档；Devin 侧栏持久状态标签+橙点未读；Copilot Agents tab 状态一览。
- **落点**：`SessionList.tsx`/`sessionListUtils.ts`/`server.mjs` sessions 元数据。
- **思路**：①逐会话状态点——BFF 已有 liveJobs 与 session 事件，把"每个会话最新 run 状态"（running/waiting/failed/idle）投影进 `/api/sessions` 列表响应，侧栏渲染彩点（活动会话现有 `sessionLiveDot` 泛化）；②未读=会话在后台期间新增 settled/waiting 事件→橙点，进入即清；③归档=软删机制旁加 `archived` 状态+过滤 tab（沿用 soft-delete 的还原路径）；④过滤 tab 加"运行中"。**先做侧栏点+过滤，不做独立 Kanban 总览页**（Devin Desktop 级别属 P2，等真并行量证据）。
- **验收**：两个会话并行跑，侧栏同时显示两个运行点；后台会话完成→橙色未读点；归档后默认列表不显示、过滤可找回。
- **不抄**：PR 合并自动归档（无 PR 流）。

### G4 diff 行级评论回喂（M）——评论即指令
- **模式**：Claude Code desktop 点任意行开评论框、多行评论 Cmd+Enter 一次提交、Claude 读评论产新 diff；Copilot"在 Files changed 里评论即 steer"。
- **落点**：`DiffReviewPane.tsx`/`InlineFileDiff.tsx` 行 hover 加评论入口；新 `diffComments.ts` 聚集评论。
- **思路**：评论=结构化引用（`file:line` + hunk 摘录 + 用户文字），聚集后一键提交→组装成一条用户消息走**既有通道**（运行中=mid-run steer/排队，空闲=新 turn），零新后端协议；模型天然读到"针对 X 文件第 N 行的意见"。回包后该文件 diff 刷新即闭环。
- **验收**：对运行产物 diff 两行各写评论→提交→模型下一轮按评论改动→新 diff 可见；运行中提交走 steer 队列并在 UI 如实标注生效时机（turn 边界）。
- **不抄**：GitHub 式评论 thread/resolve 状态机（第一刀=单向喂，不做评论生命周期管理）。

### G5 AI 自审按钮（S·纯接线）
- **模式**：Claude Code 工具栏"Review code"让 Claude 评审当前 diff、评论直接留在 diff 视图（只报高信号问题）；@codex review。
- **落点**：`DiffReviewPane` 工具栏加按钮 → BFF 已有 runtime `review` 通道。
- **思路**：按钮触发 review run（KEEP_CORE 能力早在），结论按文件锚内联到 diff 视图（复用 G4 的行锚渲染）；review 是只读动作，无权限风险。
- **验收**：点按钮→review 真跑→发现的问题挂在对应文件区块；无问题时如实显示"未发现高信号问题"。
- **不抄**：Auto-fix/Auto-merge 开关（触自主环语义，须走 DecisionPoint）。

### G6 计划审批/编辑（M·部分触 runtime）
- **模式**：Jules 计划可审批/编辑/拒绝；VS Code 计划=Markdown 可行内评论后批准；Devin Agency+30 秒无反馈自动执行；Cursor 计划前先弹澄清问题。
- **思路**：分两刀。**刀一（零后端）**：PlanChecklist 各步加评论入口，聚合为一条结构化消息回喂（同 G4 通道）——"对计划第 2 步：不要动 schema"这类意见在 plan→execute 间隙天然生效。**刀二（触 runtime）**：真编辑式改计划（增删步骤后 planner 重排产物）需要 plan-revision 接口，**先立 DecisionPoint**——与 ADR-0016 相容的形态是"用户意见作为输入喂给模型重出计划"，而非 harness 直改 task_plan。
- **验收**：刀一——plan 模式产出后对某步写意见→执行阶段模型可见并遵守；刀二以 DecisionPoint 结论为准。
- **不抄**：30 秒自动继续默认值（我们的权限档已有更明确的语义，不引入第二套计时器）。

### G7 checkpoint 文件回滚（L·依 git）
- **模式**：Claude Code 每 prompt 自动 checkpoint，rewind 四动作（对话+代码/只对话/只代码/摘要压缩）；Cline 影子 git 三恢复；OpenCode `/undo` 用 git 实现。
- **落点**：BFF `git.mjs`（影子 ref 管理）+ `turnRewind.ts`（选项扩展）。
- **思路**：turn 结束时用 `git stash create` 式影子 commit（不动索引/HEAD、不产生用户可见分支）把工作区快照挂到 session 事件；rewind 菜单从"从这里接着做/重做"扩为主流三选（含"同时回滚文件"）；回滚前显示与当前工作区的 diff 并确认（防吃掉用户手改）。非 git 工作区诚实降级为只回对话（如实文案）。
- **验收**：改两轮→rewind 到第一轮选"回滚文件"→工作区文件真回去且 diff 预览准确；非 git 工作区显示降级说明。
- **不抄**：30 天自动清理策略（本地磁盘，先不做生命周期管理）；不声称能回滚 shell 副作用（主流同样不追踪，界面如实注明——诚实闸）。

### G8 模型/提供方选择器（M·两份真源风险）
- **模式**：Crush Ctrl+L 中途换模型保留上下文；Cursor per-mode 绑定模型。
- **思路**：SettingsPanel 模型分区从只读升为可选（写入 run_config 已有配置通道，经 BFF 传 runtime）；先做 per-run 模型档选择（strong/cheap 路由映射），中途换模型待 runtime 路由证据。⚠️ 改前先确认读写同一份配置（[[permission-mode-two-sources-of-truth]] 教训：resume 读错份就会吃默认值）。
- **验收**：设置里选 provider/档位→新 run 的 model_calls 证据里真用了所选模型；resume 不丢所选。

### G9 队列逐条编辑/重排（S）
Cursor 可重排、Claude Code 用户抱怨不可编辑（做了即超越参照物）。`composerQueue.ts` 加逐条删除/编辑/上下移，纯前端+已有持久化。验收：排 3 条→删 1 改 1 换序→turn 边界按新序 flush。

### G10 预览控制台+设备切换（S–M·原 PREVIEW-4）
注入脚本转发 `console.error/window.onerror` 到已有 `/__livereload` SSE 同通道→PreviewPane 底部错误条；容器宽度预设（375/768/1280）做响应式切换；"在浏览器打开"按钮直开预览 URL。验收：页面 JS 报错→预览内可见错误条；切设备宽度渲染变化。

### G11 证据分组/批量展开（S·原 INS-4）
证据列表按类分组（validations/runs/routes/artifacts）+组级展开；`slice(0,6)`→"显示全部 N 条"；小 JSON/diff artifact 内联预览、大文件保持链接。已有 filter（`EvidenceExplorer.tsx:705`）之上补齐。

## 5. 排序与依赖

**Wave N1「安静可信赖」= G1+G2+G3+G9**（全部纯前端/BFF 已有数据，零 runtime 改动，零 DO_NOT_TOUCH）——多任务并行监控是内部引擎日用体感的第一短板，也是本次对标最一致的 table stakes。
