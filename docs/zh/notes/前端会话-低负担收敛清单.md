## 后端刚变了什么(你需要知道的上下文)

1. **自主环默认随权限档开**(§16 v1.2.27):`asteria run` 默认(reviewed_auto)现在**失败自 repair/replan、不再停下逼人 `resume`**。前端若有"等你 resume"的提示逻辑,在 auto/reviewed_auto 下基本不会再触发(只 ask_everything 或真 blocked/paused 才停)。
2. **正确性门自动收尾**(§16 v1.2.28):auto/reviewed_auto 下**验证过的 run 自动翻 `current_phase=ACCEPTED`**(不跑模型 review·只认真测试退出码)。→ `workflow.can_accept` 对这类 run 应变 false。ask_everything / 未验证 / 失败 / 有 pending 风险 promotion 的 run 仍 `can_accept=true`(合法留给人)。

## 清单(按产能杠杆排序)

### A. 验证 accept nudge 自动消失(#2 前端跟进 · 高优)
后端自动 finalize 后 `workflow.can_accept` 应为 false,「标记完成」nudge 该自然消失。**核实并收口**:
- `studio/src/features/thread/RuntimeSnapshot.tsx:164,220` `canAccept = Boolean(workflow.can_accept)`;`:264` nudge 文案「…或直接标记完成」;`:327`「标记完成」按钮。
- 期望:auto/reviewed_auto 下**验证过的 run** 不再显示「标记完成」下一步(已被后端 finalize);**未验证/ask_everything/blocked** 才显示。
- 顺带:确认「未验证」唠叨在 correctness 通过(已 ACCEPTED)时不触发(承 ADR-0021 verification 徽章逻辑)。
- 验收:真起 Studio 跑一个 reviewed_auto 验证过的任务 → 主区无「标记完成」、显示已完成/已验证徽章、无 nudge。

### B. reviewed_auto 权限文案诚实化(#3 · 一行 · 中优)
`studio/src/permissionTiers.ts:31,33` reviewed_auto 的 hint/detail 写「命令…仍会为你暂停」——**overclaim**。真相(后端已核实):逐命令暂停是 **denylist 驱动、与档无关**,只有危险命令(破坏性/联网/密钥/发布)暂停,**普通命令(pytest/git status/npm)所有档都直接跑**。`auto` 档文案(`:37` 附近「硬停止、发布和破坏性操作仍会中断」)**已准确**,照它的口径改 reviewed_auto 即可。
- 改法建议:把「命令,以及任何有风险或不可逆的操作,仍会为你暂停」→「有风险或不可逆的操作(破坏性/联网/密钥/发布类命令)仍会为你暂停;普通命令直接运行」。hint 同步。
- 别做:后端命令 allowlist(无 friction·危险命令本就该暂停·后端已是 CC denylist 模型)。

### C. 运行中注意力税收敛(#5 · 中优 · 主区=安静 loop)
承前端负担实测(只读代理),**完成后**线程已很安静(ADR-0021 白名单),但**运行中**仍有注意力税:
- **完成后工具卡不消**:`studio/src/features/thread/ConversationTurn.tsx:208-214` 持久 tool 卡——完成后可折叠/收起。
- **底部多个竞争控件并存**:next-action bar(`RuntimeSnapshot.tsx:298-351`)+ suggested chips + issue-nav(`Thread.tsx:350-361`)+ jump-to-latest(`:362-371`)。收敛成**单一权威"下一步"**,少让人选。
- 目标:运行中主区读起来像一条安静的 loop 进度(计划 checklist + 当前步),不是卡片瀑布 + 多按钮。
- 验收:真起 Studio 跑任务,运行中主区显性元素≤(计划条 + 当前步 + 真实产物卡),底部单一下一步。
