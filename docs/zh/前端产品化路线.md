## 1. 四条硬约束（同时成立）

1. **主区内容要丰富**（不止流式）——像 Cursor/Cline/Claude Code 那样把 plan/工具/diff/进度都端到主区。
2. **紧凑·高级**——主对话已刻意去框化，读起来像成熟产品；**不得重新堆卡片/加边框背景**。
3. **绝对诚实**——不渲染任何"未发生"的状态/标签/token/费用；`<think>` 清洗；压缩/截断要显式告知且原文一键可达。
4. **长任务不崩**——运行中打开高频事件流不卡死；session 可备份/还原。

## 2. 设计原则

1. **派生而非杜撰**：所有新主区（plan/todo 清单、phase 条、context 表、live diff）都从运行时**已流出的事件**派生（phase、transcript_kind plan/todo_update、cost_report、file_changed）；无数据则渲染空而非占位。richness+诚实+零后端改动一次满足。
2. **每个 token 过诚实闸**：状态/标签/表只在有真事件字段时渲染；绝不显示 $（cost_report 无定价）、绝不在终止事件前显示绿色"done"、估算 token 必标 `est.`。
3. **去框化神圣**：richness 靠排版/字重/缩进/语义色/默认折叠，**不**靠新卡片背景。新元素（phase 条、清单、context 表）是复用 tokens 的安静内联条。响亮色只留给需人决策的（diff/权限/错误）。
4. **稳定是结构性的**：完成的 turn 变不可变、廉价渲染（memo/虚拟化）节点；只有流式尾部活跃重渲染。切会话缓存不清空。重连带 sequence 游标做无缝幂等回填；磁盘 JSONL 永远是真源。
5. **一条 transcript，统一块可供性**：收敛到既有 turn/step 模型为原子单位，往上加折叠/跳转/锚点，而非再开并列面板。

### I11 ✅ 主线内联每文件 Keep/Revert（M · 2026-07-03）
- **落地**：per-turn 文件 chip 上加 hover 露出的 **Keep**(git stage)/**Revert**(git checkout) 内联按钮，复用既有 `api.gitStage`/`gitDiscard`，无需先进 diff-focus 侧栏选文件再操作。诚实语义：Revert=`git checkout -- <path>` 丢弃该文件全部未提交改动（destructive→`window.confirm`），Keep=`git add`（标记已审）；每 chip 独立 busy/resolved 态，成功后显 "Kept"/"Reverted" 并禁用；toast 反映真 git 结果，失败不谎报成功。
- **只在最后一轮露出**（`isLast`）：Revert 是整文件未提交改动回滚而非"该轮 delta"，只在当前轮暴露避免历史轮误导（诚实边界）。
