# 真实使用证据包

本文定义 alpha / 内测阶段用户在本机真实使用 Asteria 后，应该导出的最小诊断证据。目标不是证明“模型一定快”，而是把网络环境、provider latency、规划质量、验证质量、promotion 风险和用户体验问题分开。

## 1. 导出命令

在真实项目目录中运行：

```powershell
asteria evidence-bundle --root . --json
```

默认输出到：

```text
.asteria/evidence_bundles/evidence-<timestamp>.zip
```

也可以指定路径：

```powershell
asteria evidence-bundle --root . --output .asteria/evidence_bundles/my-run.zip
```

该命令只读，不会重新调用模型，不会修改任务状态。

证据包是 workspace-local 产物：默认只导出当前 workspace 内 `.asteria/` 的脱敏证据。用户目录下的全局 `.asteria/` 只允许读取版本、recent workspace 指针、模型 route 配置是否存在等摘要，不能打包本机 route/key 文件、账号文件或跨 workspace 的 session/run。

## 2. 默认包含

证据包默认包含脱敏后的运行证据：

- `manifest.json`：Asteria 版本、Python/系统信息、模型 route 聚合指标、完成度评估。
- `.asteria/model/real_model_gate_report.json`
- `.asteria/model/real_model_smoke_summary.json`
- `.asteria/model/capability_profile.json`
- `.asteria/verification/real_model_acceptance_validation.json`
- `.asteria/verification/real_model_acceptance_core.json`
- `.asteria/validation_runs/<validation-run-id>/summary.json`
- `.asteria/ops/usage_signals.jsonl`
- `.asteria/ops/usage_signal_analysis.json`
- 最近若干 run 的 `run.json`、`cost_report.json`。
- 最近若干 run 的 `events.jsonl` tail。
- 最近若干 run 的 `model_calls.jsonl` tail。
- 最近若干 run 的 `task_execution_evidence.jsonl`、`worker_results.jsonl`、`validation_results.jsonl` tail。
- 当前 workspace id、workspace name、相对路径摘要、git branch 摘要。

这些文件用于复盘：

- 用户是否按包装后的 `gate` / `validation` / `run` 路径使用。
- strong / medium route 是否都真实调用。
- streaming 是否有首包、chunk、duration、deadline、fallback 证据。
- 失败发生在 provider deadline、规划、验证、repair、promotion 还是人工决策。
- 候选产物是否被验证、promotion queue 是否有 unresolved 风险。
- validation-run probe 是 passed、failed 还是 missing_evidence；missing_evidence 只表示本轮样本未覆盖，不能当作通过。
- 后台使用信号是否显示产物被接受、阻塞原因是否重复、旧 blocker 是否已经被新 evidence 修复。

## 3. 默认排除

证据包不得包含：

- API key、token、authorization、password、secret。
- `.env`、`.env.*`。
- `secrets/`。
- `.git/`。
- `*.pem`、`*.key`。
- `C:\Users\Administrator\.asteria\model.routes.local.ps1` 或其他本机 route/key 文件。
- `%USERPROFILE%\.asteria\accounts\`、全局 cache、全局 logs 和其他 workspace 的 recent session/run。
- 未经授权的业务源码全文。

`evidence-bundle` 会按 key 名和常见文本模式做脱敏，但用户仍应把它视为诊断材料，在分享前确认没有私有业务内容。

## 4. 诊断排障时的额外说明

证据包不会自动判断网络环境。以下信息只用于内测支持、诊断排障或运维复盘，不属于普通用户运行时的显性主流程。需要提交诊断材料时请补充：

- 是否使用 VPN / 代理。
- 是否在国内网络直接访问 GLM / MiniMax。
- 运行的大致时间段。
- 你看到的体感问题：长时间无输出、首包慢、执行慢、验证反复、还是最终报告不可信。
- 本次任务类型、期望结果、最终产物是否愿意接受。
- 最大阻塞点：安装/初始化、模型等待、规划不准、验证不可信、权限/审批困惑、报告看不懂、还是产物质量不达标。
- 信任问题：哪些操作让你不敢继续、哪些证据不足以让你相信结果。

这些信息会和 `model_calls.jsonl` 的 `first_chunk_ms`、`duration_ms`、`streaming.mode`、`deadline_ms` 共同判断问题归因。

这些补充信息应进入运维侧 `UsageSignal` / `OpsInsight` 对象，并与 `run_id`、`evidence-bundle`、失败归因和 roadmap task 绑定。当前入口是 `asteria ops-signal`，写入 `.asteria/ops/usage_signals.jsonl`；`asteria ops-signal --summary --analyze` 会生成 `.asteria/ops/usage_signal_analysis.json`。该能力按后台埋点和脱敏证据指纹设计，不作为普通用户显性的反馈流程。

## 5. 当前完成度口径

截至当前阶段，Asteria 已经具备受控 alpha dogfooding 的核心闭环：

- 本地优先 runtime 状态、任务、证据、成本和报告落盘。
- strong/medium provider route、streaming telemetry、deadline budget 和 heartbeat。
- `gate-status`、`gate`、`validation`、`capability-report` 控制面。
- validation/core acceptance、release gate、promotion release risk 阻断。
- candidate isolation / merge gate / promotion queue 的基础能力。

2026-06-01 的 alpha.1 最小真实证明已经完成：strong route 在 `glm-5.1` 下恢复健康，core acceptance 与 validation gate 通过，1 个真实 provider scoped `validation-run` 完成，证据包包含 validation summaries 与后台使用信号分析。

尚未完成到“可无条件放量”的部分：

- subagent selection、readonly fanout、readonly write-tool blocking、disjoint write unsafe fanout 和 parent loop stop 仍需要真实样本 probe。
- route guidance 仍需要 review，不应因为一个成功样本直接扩大批次。
- damaged_memory / multi_run_conflict 恢复压力测试还未补齐。
- candidate worktree / promotion queue 的人工审批默认策略还需要 DecisionPoint。
- 用户可见的长任务进度和证据浏览仍要继续产品化。

因此，alpha.1 可以进入内部受控试跑候选包装；下一步不是无条件放量，而是用 3-5 个 scoped 真实任务补齐 missing probe，并让 `ops-signal --analyze`、weekly report 和 roadmap 持续生成下一轮修复项。
