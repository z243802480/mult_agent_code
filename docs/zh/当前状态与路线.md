# 当前状态与路线

更新时间：2026-05-29

本文是 Asteria 当前阶段的事实入口。进入开发前先读根目录 `AGENTS.md`，再读本文；需要展开设计时再读 `docs/zh/文档导航.md` 中列出的专题文档。

本文只保留当前事实、有效架构、剩余差距和下一步优先级。历史流水账、已完成的阶段性计划、旧 validation 次数和旧 release gate 记录不再作为当前状态依据；需要追溯时看 git history。

## 1. 当前阶段

Asteria 当前处于：

```text
模型主导的 Asteria Runtime OS 收口阶段
```

产品目标是：

```text
本地优先、可恢复、可审计、可控成本的长任务自主开发运行时。
```

核心原则：

- 模型负责在能力边界内判断下一步。
- Runtime 负责权限、预算、schema、上下文、候选工作区、证据、恢复和 gate。
- CLI/Studio/报告都消费同一套 `.asteria/` evidence，不各自发明状态。
- 历史 validation 和 runtime matrix 通过记录只是回归健康信号，不等同于长期自主能力完成。

## 2. 已落地的主线能力

### Runtime OS 基线

- `init`、`plan/run`、`execute`、`status`、`debug`、`replan`、`review`、`accept`、`gate-status`、`validation` 等主入口可用。
- `.asteria/` 持久化 run、task、model call、worker、runtime profile、context mount、task execution evidence、validation、review、final report 等对象。
- TaskGraph、WorkerInvocation、WorkerResult、RuntimeProfile、ContextMount、TaskExecutionEvidence、MergeGate 已进入运行证据链。
- Candidate workspace、merge gate、promotion queue 和 protected path policy 已作为写入边界的一部分。

### 模型可见能力和上下文

- PromptEnvelope、ContextEnvelope、CapabilityManifest、AgentRoleContract 已进入模型调用证据。
- ModelToolSurfaceAdapter 已把模型侧 `read/list/search/edit/shell/test/todo` 原语映射到内部 registry，并保留 `model_tool_name` 审计字段。
- Tool、MCP、Skill 仍是分离执行入口，但复用 capability decision evidence。
- 任务级 capability catalog 已记录 visible / selected / skipped / blocked 和原因。
- ContextBudgetMeter 已记录 request-level context estimate、context window ratio、section 归因和重复内容信号。

### Agent Harness 循环决策

- `AgentLoopDecision` 已成为稳定 schema。
- 模型下一步动作限定为：

```text
tool | subagent | repair | replan | ask | stop
```

- 每个 action 必须带 reason、target_task_id、capability_ref、expected_observation、risk、budget_hint、evidence_refs。
- `agent_loop_decisions.jsonl` 记录模型或 Runtime 代写的下一步决策。
- `agent_loop_execution_results.jsonl` 记录 Runtime 对该决策的分派结果。

当前六类 action 的闭环状态：

- `tool`：进入 Tool Gateway / verification 链路。
- `subagent`：校验 `capability_ref.type == "subagent"`、target_task_id、risk、budget_hint 后，写入 WorkerInvocation / WorkerResult dispatch evidence。
- `repair`：映射到 debug/recovery 链路。
- `replan`：映射到 replan 链路。
- `ask`：Runtime-owned ask 可创建 DecisionPoint，并在 status 中显示精确 `decide --decision-id ...`。
- `stop`：映射到 status/debug 报告和停止说明。

### Gate 和状态面

- RuntimeReadinessGate 已把 model role/deadline/streaming、route guidance、context pressure、observation decision、agent loop execution、capability selection 纳入 readiness 判断。
- 最新 model progress、AgentLoopDecision、AgentLoopExecutionResult 已进入 `status` / `sessions --context`。
- `gate-status` 对 validation failure 的下一步优先使用 Runtime execution result，而不是只按模型意图推断。
- 命令暴露面已开始分层：普通用户入口优先 Goal / Plan / Status / Review / Accept / Debug；raw evidence、validation、gate、capability report 属于 maintainer/Inspector 层。

### Provider 和 deadline

- model call 记录 role contract、route、deadline、streaming telemetry。
- strong route timeout/deadline 可以 fallback 到 medium，并在 model-check / model_calls evidence 中记录。
- review / recovery / validation timeout 不再只停在 provider/review 层，会写入 AgentLoopDecision，并进入 repair / replan / ask / stop 链。

## 3. 当前主要差距

### 3.1 Agent loop 仍需从 dispatch 走向多轮自动循环

现在 Runtime 已能校验和分派 `AgentLoopDecision`，但仍偏“一轮 action dispatch”。下一步要让 loop runner 在每次 observation 后自动回到模型，直到 stop、ask、预算/gate 阻断或完成。

重点差距：

- tool/subagent observation 需要统一回灌给模型。
- repair/replan/ask/stop 的后续状态迁移还需要更统一。
- subagent dispatch 当前已有 worker evidence，但还不是完整的子 agent 多轮执行器。

### 3.2 ContextBudgetMeter v2

已具备 request-level 和 section-level 粗归因，但还需要：

- compact boundary evidence：压缩前后 token、保留/丢弃 section、恢复摘要、evidence refs。
- subagent 隔离 context window，避免子任务污染主线。
- 文件级 hash/diff 降噪，减少重复读取未变文件。

### 3.3 Capability Selection Audit

已生成 catalog 和 capability decision evidence，但还需要：

- 把 catalog 注入更多模型入口。
- 对齐模型真实工具 / Skill / MCP / subagent 选择和 catalog 选择状态。
- 报告“可见但未用”“被权限阻断”“被风险策略阻断”“模型未选择”的原因。

### 3.4 真实小任务滚动验证

固定 validation suite 是回归门槛，不是产品能力证明。还需要连续 3-5 个 scoped 真实开发任务，观察：

- route/deadline 是否稳定。
- failure 是否进入 loop decision。
- context pressure 是否可解释并触发 compact。
- capability selection 是否和 catalog 一致。
- 最终产物和验证是否可复现。

### 3.5 Studio 消费层

Studio 不作为 Runtime P0 阻塞项，但需要继续只消费 runtime evidence：

- 主线程展示 user_progress、artifact、DecisionPoint、下一步。
- Inspector 展示 raw evidence、route、schema refs、context/capability 诊断。
- 默认主屏不暴露 maintainer 命令。

## 4. 当前研发优先级

1. **Agent loop runner 多轮化**：把 `AgentLoopDecision -> execution result -> observation -> next decision` 串成受 gate 约束的循环。
2. **Subagent 执行器深化**：从 dispatch evidence 进入真正的子 agent 多轮执行、隔离 context、worker completion/failed observation。
3. **ContextBudgetMeter v2**：compact boundary、subagent context isolation、文件 hash/diff 降噪。
4. **Capability Selection Audit 深化**：模型真实选择与 catalog 对齐，进入 gate/report。
5. **真实小任务滚动验证**：用 3-5 个 scoped 任务验证 loop、context、capability、provider 和产物质量。
6. **Studio 消费质量**：只补 user_progress 主线和 Inspector 可读性，不让 UI 反向驱动后端架构。

## 5. 当前验证基线

最近一次本地回归：

```text
pytest: 637 passed, 1 skipped, 29 deselected
mypy src: passed
ruff check: passed
```

验证注意：

- `validation` / `runtime matrix` 是回归健康守卫，不是长期自主能力完成标准。
- 真实 provider 放量前仍需重新生成目标 workspace 下的 `gate-status --json`、`model-check`、capability report、context budget 和 evidence bundle。
- 不沿用旧机器、旧 route、旧 run 的历史通过记录判断当前状态。
