## 4. 综合下一步计划

唯一研发主线仍是 **S74 Post-S73 Beta convergence**：

1. 已完成真实单文件、doc update、bugfix 与明确委派任务；`execution_preferences` 现只保留用户明确的 delegation/read scope，Runtime 首轮校验 required delegation，完成态清除已解决 DecisionPoint。
2. 下一步聚焦减少 subagent 路径的重复 model/repair 回合；目标是保留父子 evidence 与权限隔离，同时把小任务恢复到分钟级。
3. 默认主路径保持 Claude Code/Codex 风格：模型驱动工具与验证，Runtime 只保留必要护栏。
4. Asteria 特有能力必须证明能提升完成率、速度、安全或恢复能力；无收益的复杂路径保持 opt-in、回退或删除。
5. 在 subagent 小任务耗时与调用数收敛前，不扩大默认使用面；基于真实证据决定继续优化或收缩复杂能力。
6. 2026-06-09 方法校正：调用次数、repair 和耗时按任务类型作为产品 SLO 与回归证据；Runtime 硬边界只处理权限、安全、不可逆操作、资源 hard-stop 和可证明的无进展循环。现有复杂代码按 Golden Trace 做价值审计，不整体推倒，也不默认保留。
7. 复杂度清算采用 ADR-0011 四道裁决门：愿景与实现分离，优先复用成熟产品的稳定驾驭方式；确认劣质实现后停止局部修补，保留有价值的能力契约并果断替换或删除实现。
8. 第一批清算已执行：native `tool_use` 从简单任务自动默认路径退回显式 opt-in；Phase 2 stability 与 Run Health 不再用固定 model-call / repair / replan 次数制造硬失败，效率越界进入 SLO warning，证据缺失、blocked terminal、资源体积失控仍保持硬失败。
9. 产品进展投影子系统开始整体替换：Studio 主会话改为 Session Transcript 单一真源，不再从 `runtime_progress`、`main_path` 或 summary 合成过程和最终回答；旧 run 仅走隔离 legacy events adapter。
10. 控制面清算已删除全局 `RuntimeReadinessGate`：权限、sandbox、merge、promotion 等风险回到动作边界；`gate-status` 只负责发布 preflight，`validation-run` probe 直接验证目标行为，不再维护 readiness 绕过白名单。
11. 恢复链清算已删除默认 Run 的自动 Review/Debug/Replan 与 review-driven Goal policy；失败 observation 回到当前 Session Agent Loop，显式 `review` 只查证和反馈，显式 `accept` / `debug` 保留兼容。
12. 全系统复杂度审计已完成首轮完整裁决矩阵：删除无人消费的 FollowUpTaskPlanner / keyword DecisionPolicy，并删除 real-model smoke/gate/acceptance 的伪造 review/eval/final 与 timeout salvage。
13. 产品架构已按官方竞品机制重新裁决：连续 Session Agent Loop 是产品中心；状态机、TaskGraph、固定 Agent 类只允许作为可替换实现，不得主导愿景、Studio 或默认恢复。竞品机制与后续批次见 `plans/S74_REFERENCE_PRODUCT_BASELINE.md`。
14. 后续 P0 按完整责任链推进：先替换 DebugCommand 独立 repair engine，再删除 goal_policy 重复投影与 Run 私有报告耦合，随后收敛 context/capability 真源，最后用 3–5 个真实 Beta 任务裁决剩余编排和运维壳。

详细执行与停止规则见 [`plans/S74_POST_S73_BETA_CONVERGENCE_PLAN.md`](./plans/S74_POST_S73_BETA_CONVERGENCE_PLAN.md)。
