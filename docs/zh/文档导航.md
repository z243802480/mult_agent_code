# Asteria 中文文档导航

更新时间：2026-06-02

本文是 `docs/zh` 的唯一导航入口。新 agent 或维护者进入项目时，先读根目录 `AGENTS.md`，再读 [当前状态与路线.md](./当前状态与路线.md)，然后按本文选择详细文档。

## 1. 文档维护原则

- 主线只保留当前事实、永久设计、稳定协议、命令参考和当前执行计划。
- 过时的过程性计划及时删除；需要追溯时看 git history。
- 设计类永久文档可以保留，但必须说明当前作用。
- Studio、验证、真实模型、工程治理等专题文档不进入 Runtime 后端默认开发主线，除非当前任务需要。Studio 是独立产品交互面，不决定后端优先级，但其用户交互设计长期有效。

## 4. 文档状态

文档状态以本文的默认必读、按需阅读和归档分区为准。历史审计报告见 [reports/文档状态审计.md](./reports/文档状态审计.md)，只作为清理过程证据，不再作为当前事实源。新增文档必须选择状态：

- `current`：当前事实或当前执行计划。
- `design`：长期有效的产品、架构或协议设计。
- `reference`：按需参考，不作为默认开发入口。
- `generated`：由命令或运行证据生成，可重新生成，不作为手写设计源。
- `report`：验收、dogfooding、审计等历史证据，默认放入 `docs/zh/reports/`。
- `deleted`：已删除的过程性旧计划。

## 5. 生成物与报告

- [自动路线图.md](./自动路线图.md) 是 `roadmap-update` 的默认生成输出，保留在顶层以匹配命令实现；其内容以最新 evidence 生成结果为准。
- `docs/zh/reports/` 保存历史验收、批次验证、dogfooding 和文档审计报告，不参与当前实现决策。

## 6. 归档

`docs/zh/archive/` 只保留历史参考，不参与当前实现决策。过时过程性计划优先删除，不再继续向 archive 堆积。
