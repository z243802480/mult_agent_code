# 产品化内测检查清单

本文用于干净机器或干净虚拟环境中的首轮产品化内测。目标是验证安装包路径、真实 provider route、控制面、证据导出和小任务体验，而不是在开发仓库里重复跑源码测试。

## 1. 内测准入

开始前必须满足：

- 仓库侧 `package-check --json` 通过。
- 已生成 wheel：`dist/asteria_runtime-0.1.0-py3-none-any.whl`。
- 安装手册、灰度手册、真实使用证据包文档已更新。
- 目标机器的 GLM / MiniMax key 只放在环境变量或本机私有 `C:\Users\Administrator\.asteria\model.routes.local.ps1`，不得写入仓库。
- 内测任务只选择低风险小任务：文档更新、小文件产物、小 CLI、多文件小工具、测试修复或受控重构。

## 2. 干净环境安装

在目标机器执行：

```powershell
$base = Join-Path $env:TEMP "asteria-alpha"
$venv = Join-Path $base "venv"
$workspace = Join-Path $base "workspace"
python -m venv $venv
$python = Join-Path $venv "Scripts\python.exe"
$asteria = Join-Path $venv "Scripts\asteria.exe"
& $python -m pip install --no-index --find-links <wheel目录> asteria-runtime
& $python -m pip install pytest
& $asteria version --json
& $asteria init --root $workspace
```

其中 `<wheel目录>` 是包含 `asteria_runtime-0.1.0-py3-none-any.whl` 的目录。

## 3. 路由配置

推荐把 route 放在目标机器本机私有文件：

```powershell
New-Item -ItemType Directory -Force C:\Users\Administrator\.asteria
notepad C:\Users\Administrator\.asteria\model.routes.local.ps1
```

参考模板：`templates/model.routes.gray.example.ps1`。

配置后运行：

```powershell
& $asteria doctor --root $workspace --json
& $asteria model-check --root $workspace --tier strong --json
& $asteria model-check --root $workspace --tier medium --json
```

如果使用国内网络直连 GLM / MiniMax，请在内测记录里注明“未使用 VPN”；如果使用 VPN / 代理，也请注明。这个信息不会自动进入证据包，需要人工补充。

## 4. 门禁顺序

固定顺序：

```powershell
& $asteria gate --root $workspace --json
& $asteria real-model-gate --root $workspace
& $asteria real-model-acceptance --root $workspace --suite gray --python $python
& $asteria acceptance --root $workspace --suite core --allow-fake
& $asteria acceptance-gate --root $workspace --suite core --min-scenarios 10 --min-capabilities 10
& $asteria gate-status --root $workspace --json
```

只有当 `gate-status` 同时满足以下条件，才进入 12 个小真实任务批次：

- `release_ready=true`
- `route_guidance.status=healthy`
- `gates.gray_suite.ok=true`
- `gates.core_acceptance.ok=true`
- `promotion_release_risks.pending=0`
- `promotion_release_risks.blocked=0`

如果 `route_guidance.status=blocked`，先不要放量；导出证据包后分析 route、provider deadline 和网络环境。

## 5. 证据导出

每轮内测结束后运行：

```powershell
& $asteria capability-report --root $workspace
& $asteria evidence-bundle --root $workspace --json
```

把输出里的 `bundle_path` 作为本轮分析材料。证据包会脱敏并排除 API key、本机 route 文件、`.env`、`secrets/`、`.git/`、证书和私钥。

提交证据时额外说明：

- 是否使用 VPN / 代理。
- 是否国内网络直连 GLM / MiniMax。
- 运行时间段。
- 体感问题：首包慢、长时间无输出、执行慢、验证反复、promotion 阻断，还是最终报告不可信。

## 6. 当前完成度判断

当前版本可以进入受控 alpha 内测：核心 CLI/runtime loop、真实 provider gate、gray/core acceptance、streaming telemetry、heartbeat、capability profile、release gate、promotion risk 阻断和证据导出都已具备。

尚不应宣布大规模放量或 1.0：

- strong goal_spec route 必须在目标网络环境证明稳定。
- 12 个小真实任务批次需要 `route_guidance.status=healthy` 后再启动。
- candidate worktree / promotion queue 人工审批默认策略还需要在下一轮真实小任务后做 DecisionPoint。
